# دمج التوجيه الذكي مع ترحيل الرسائل

- تم ربط `RelayRoutePlanner` بمسار إعادة محاولة طابور الترحيل في `ChatScreen`.
- يستخدم التطبيق قائمة اتصالات Wi-Fi Aware النشطة فقط، ولا يرسل إلى مجرد الأجهزة المكتشفة.
- يتم ترتيب القفزات التالية واختيار أفضل مرشحين اثنين، مع استبعاد معرفات الأجهزة الموجودة في `relayPath`.
- يمكن تضمين `routeHints` موثوقة في الحزمة لكل peer: `signal`, `successRate`, `knownDestination`, `estimatedHops`, `batteryPercent`, `isCharging`, `isBusy`. عند غيابها تستخدم قيم محافظة/افتراضية.
- إذا لم ينجح إرسال Aware، يجرب Bluetooth المتصل، ثم LAN القديم كمسار توافق أخير فقط.
- نجاح كتابة الحزمة إلى قناة النقل لا يعني وصولها إلى المستلم النهائي؛ تبقى سياسة ACK والطابور مسؤولة عن التسليم.

## حدود معروفة

- لا توجد بعد آلية موزعة لتبادل routeHints موثوقة وموقعة، لذلك التوجيه الذكي يستفيد من التلميحات إن وجدت، وإلا يعتمد على بيانات افتراضية ولا يستطيع معرفة الوجهة البعيدة فعليًا.
- واجهة Bluetooth الحالية لا تعرض قائمة جلسات موثقة مفصلة، لذا يستخدم البث الأصلي كبديل عند غياب مسار Aware.
- لم يتم تشغيل Flutter analyze أو اختبارات الأجهزة في هذه البيئة.
