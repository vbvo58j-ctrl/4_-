# إصلاح مصافحة LAN في Mesh

- لم تعد إعلانات UDP وحدها تُنتج حدث مستخدم قريب أو تسمح بتمرير رسائل Mesh.
- أضيفت مصافحة TCP ببروتوكول `blousab-lan-v1` مع nonce عشوائي لكل جلسة، والتحقق من رد الطرف المقابل قبل الإرسال.
- يرفض مستمع TCP أي إطار بيانات يسبق المصافحة، ويربط الرسائل بهوية النظير الذي اجتاز المصافحة على الاتصال نفسه.
- خدمة Mesh تتحقق من أن `senderId` أو آخر عنصر في `relayPath` يطابق هوية النظير المصادق عليه قبل قبول الحزمة أو تمريرها.
- تبقى إعلانات UDP وسيلة اكتشاف أولي فقط، وليست إثبات هوية.

**حدود أمنية مهمة:** هذه مصافحة بروتوكولية متبادلة وتحد من الأجهزة التي لا تشغّل بروتوكول بلوساب، لكنها ليست مصادقة تشفيرية لهوية المستخدم؛ فالـ nonce لا يثبت وحده ملكية الحساب أمام مهاجم قادر على انتحال `peerId`. يلزم لاحقًا ربطها بمفاتيح عامة/خاصة وتوقيع تحدي المصافحة للتحقق التشفيري من الهوية.
