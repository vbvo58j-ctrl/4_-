# المرحلة 6 — اشتقاق مفتاح Wi‑Fi Aware بمصافحة X25519

## ما تغير
- ألغيت اشتقاق كلمة مرور NDP من `userId` العام؛ لم تعد المعرفات العامة مصدراً لأي سر مشترك.
- ينشئ كل طرف مفتاح X25519 مؤقتاً مستقلاً لكل `PeerHandle` ولكل مصافحة.
- يرسل الطرف المفتاح العام المؤقت داخل رسالة الهوية `BLUSAB_WIFI_ID|2`، وتغطيه توقيعة Ed25519 على بيان الهوية.
- رسالة الإثبات `BLUSAB_WIFI_PROOF|2` توقع transcript موحداً يضم معرفي الطرفين، nonce كل طرف، والمفتاحين المؤقتين. ترتيب البيانات قانوني وثابت بحسب userId، لذلك ينتج transcript واحد على الطرفين.
- بعد تحقق توقيع الإثباتين فقط، يحسب الطرفان X25519 shared secret محلياً، ثم HKDF-SHA256 مع salt مشتق من transcript وcontext ثابت خاص ببلوساب.
- يحول الناتج إلى 63 محرفاً سداسياً عشرياً قابلاً للطباعة، ضمن قيود كلمة مرور Wi‑Fi Aware (8–63 محرفاً)، ويُستخدم فقط مع جلسة المصافحة وPeerHandle المطابقين.
- `wifiVerified` لا يصدر قبل اكتمال إثبات الطرفين واشتقاق PSK. ويظل فتح مسار البيانات مشروطاً باختيار المستخدم كما في المرحلة السابقة.
- تزال قيمة PSK والمفتاح العام المؤقت المخزن عند فشل المصافحة أو انتهاء المهلة أو فقدان النظير أو إيقاف Wi‑Fi Aware.

## توافق المكتبات والمنصة
- يستعمل X25519 من Bouncy Castle lightweight API المضمنة أصلاً في `bcprov-jdk18on:1.80`؛ لا يعتمد على وجود X25519 provider في إصدار Android.
- `minSdk` الحالي 24، بينما إنشاء مسار بيانات Wi‑Fi Aware نفسه يظل محصوراً في Android 10 / API 29 أو أحدث وفق الكود السابق.
- لا يُنقل مفتاح Ed25519 الخاص من Flutter Secure Storage إلى Kotlin؛ توقيع transcript يستمر عبر آلية التوقيع الموجودة في التطبيق.

## حدود الحماية
- كلمة مرور NDP أصبحت مشتقة من سر X25519 وليست قابلة للاشتقاق من أسماء/معرفات المستخدمين. هذا يعالج سرية كلمة مرور رابط Wi‑Fi Aware.
- لا يعني ذلك أن حمولة التطبيق أصبحت مشفرة E2E تلقائياً. يلزم تشفير كل packet على مستوى التطبيق (مثل AES-GCM) مع nonce/counter فريد، AAD، ومنع replay وإدارة/تدوير مفاتيح مستقلة.
- التوقيع الذاتي يثبت حيازة مفتاح Ed25519، ولا يثبت وحده أن المفتاح يعود لشخص معروف؛ تبقى مقارنة QR/بصمة المفتاح خارج القناة لازمة للثقة الشخصية.

## التحقق
- تمت مراجعة اتساق transcript ومواضع استخدام PSK وحراسة جلسة الاتصال يدوياً.
- لم يتوفر Flutter أو Dart أو Gradle أو Android SDK في بيئة التنفيذ؛ لذلك لم ينفذ `flutter analyze` أو Gradle build أو APK أو اختبار هاتفين. يجب اختبار تبادل X25519 المتناظر والاتصال الفعلي على جهازين قبل اعتبار المرحلة جاهزة للإنتاج.
