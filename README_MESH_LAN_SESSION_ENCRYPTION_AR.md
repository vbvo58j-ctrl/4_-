# تشفير جلسات LAN في بلوساب

## ما تغير
- ترقية بروتوكول مصافحة LAN إلى `blousab-lan-v2`.
- إنشاء مفتاح X25519 مؤقت لكل اتصال TCP.
- توقيع المفتاح المؤقت ضمن نص المصافحة بمفتاح Ed25519 الدائم، وربط التوقيع بهوية المرسل والمستقبل والـNonce والمفتاحين المؤقتين.
- اشتقاق مفتاح جلسة مستقل باستخدام HKDF-SHA256.
- تشفير كل إطار LAN باستخدام AES-256-GCM مع AAD ثابت خاص ببروتوكول بلوساب.
- تطبيق التشفير على الإرسال الفردي، والتحكم/الإقرارات، والبث إلى عدة مستخدمين، وليس على مسار واحد فقط.
- رفض الإطارات غير المشفرة بعد اكتمال المصافحة.

## حدود التحقق
- لم يتم تشغيل `dart analyze` أو `flutter test` أو بناء APK لأن أدوات Flutter/Dart غير متاحة في بيئة التعديل.
- لم يتم اختبار التوافق على هاتفين فعليين؛ يجب تحديث الجهازين إلى إصدار البروتوكول v2 معًا، لأن v1 وv2 غير متوافقين.
- لا تزال الثقة عند أول اتصال تعتمد على TOFU؛ توقيع Ed25519 يمنع انتحال الطرف بعد تثبيت المفتاح، لكنه لا يمنع استبدال المفتاح في أول اتصال. يلزم تأكيد بصمة/QR خارج القناة لإغلاق ذلك.
- التشفير هنا بين طرفي جلسة LAN المباشرة. لا يعني ذلك تلقائيًا تشفيرًا طرفيًا موحدًا عبر كل قفزات Mesh؛ يجب أن تبقى حمولة الرسالة نفسها مشفرة طرفيًا عند الحاجة.
