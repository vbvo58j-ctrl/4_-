# مرحلة Mesh — استقبال الملفات على مستوى التطبيق

تم نقل استقبال حزم `file_chunk` و`file_chunk_end` وتجميعها وفحص CRC32 وحفظ الرسالة النهائية إلى `MeshRuntimeService`، بحيث لا يعتمد الاستقبال على بقاء `ChatScreen` مفتوحة.

- استقبال الحزم عبر Bluetooth بعد المصافحة، وWi-Fi Aware، وLAN بعد مطابقة هوية المرسل مع قائمة مستخدمي Blousab المكتشفة.
- حفظ كل جزء بصورة دائمة، مع تسلسل معالجة الأجزاء حسب `transferId` لمنع تعارض وصول الجزء نفسه عبر مسارين بالتزامن.
- إنشاء سجل النقل عند وصول `file_chunk_end` حتى إذا لم يصل أي جزء، ثم طلب الأجزاء الناقصة.
- إعادة طلب الأجزاء الناقصة دوريًا بعد إعادة تشغيل التطبيق أو عودة الاتصال، عبر Wi-Fi Aware ثم Bluetooth ثم LAN.
- إعادة طلب جميع الأجزاء عند فشل الحجم أو CRC32، وعدم اعتماد الملف قبل نجاح الفحص.
- حفظ مرفق الرسالة في `MessageStore` وإرسال إقراري التسليم والقراءة بعد اكتمال الملف.
- أزيل من شاشة المحادثة منطق استقبال وتجميع الأجزاء القديم؛ بقي إرسال الملفات ضمن الشاشة.

## حدود التحقق

تم فحص بنية التعديلات ووجود الاعتماديات في `pubspec.yaml`، كما تم فحص سلامة ZIP. لم تتوفر أدوات Flutter/Dart في بيئة العمل، لذلك لم يتم تشغيل `dart analyze` أو `flutter build`، ولم يتم اختبار النقل بين أجهزة فعلية. يلزم اختبار ثلاثي الأجهزة خصوصًا لمسارات ACK عبر وسيط، ولحالة فقدان الاتصال أثناء التجميع.
