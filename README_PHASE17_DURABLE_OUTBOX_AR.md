# المرحلة 17 — صندوق إرسال دائم وإعادة المحاولة على مستوى التطبيق

## ما تم ربطه
- أضيفت إعادة محاولة لصندوق الرسائل الفردية من `MeshRuntimeService` على مستوى التطبيق، وليس من `ChatScreen` فقط.
- تبدأ محاولة الإرسال عند تشغيل خدمة Mesh، وتتكرر دورياً، وتُستدعى مجدداً عند توثيق اتصال Bluetooth أو LAN أو Wi-Fi Aware.
- يعاد إرسال **نفس حزمة Ratchet المشفرة المحفوظة**؛ لا يعاد استدعاء `encrypt` عند إعادة المحاولة، حتى لا تُستهلك مفاتيح سلسلة جديدة لنفس الرسالة ولا تختلف هوية الحزمة بين المحاولات.
- تدعم المحاولة مساراً مباشراً موثقاً عبر Wi-Fi Aware أو Bluetooth أو LAN، ثم next-hop موثوقاً من دليل Mesh، وعند عدم وجود مسار تضاف الحزمة إلى طابور الترحيل. رسائل المجتمع تعاد كحزم Group E2E opaque عبر مسارات البث.
- لا تُحذف الرسالة من صندوق الإرسال عند نجاح كتابة socket؛ لا تُحذف إلا بعد استلام إيصال `delivery_ack` موثّق ومشفّر. إيصالات الفردي تستخدم Pairwise Ratchet، وإيصالات المجتمع تستخدم Group E2E epoch.
- أضيف backoff تصاعدي للمحاولات، مع بقاء الرسائل لمدة تصل إلى 7 أيام، وحد أقصى 1000 عنصر في الصندوق.
- الكتابة إلى ملف الصندوق تتم عبر ملف مؤقت ثم rename، ويُرفض التعامل مع تلف الملف على أنه صندوق فارغ كي لا تُمحى الرسائل المحفوظة بصمت.
- إصلاح إعادة محاولة نقل الملفات في شاشة المحادثة: نجاح كتابة أجزاء الملف لا يساوي التسليم، ولذلك يبقى سجل النقل والملف المحلي حتى إيصال التسليم النهائي.
- يطلب المستقبل الأجزاء الناقصة بعد عودة الاتصال، ويستجيب runtime لدى المرسل بطلبات الأجزاء المفقودة دون اشتراط فتح شاشة المحادثة. إيصال اكتمال الملف الفردي يستخدم Pairwise Ratchet، وإيصال الملف الجماعي يستخدم Group E2E؛ لا يوجد fallback لإيصال مكشوف.
- يستقبل runtime رسائل المجتمع ويصدر delivery_ack جماعياً مشفراً حتى عندما تكون شاشة المحادثة مغلقة؛ إيصال القراءة يبقى مرتبطاً بفتح المحادثة.

## حدود مهمة
- هذا ليس Android foreground service ولا WorkManager ولا boot receiver. بعد إغلاق التطبيق قسرياً أو إيقافه من النظام لا يمكن تنفيذ الإرسال في الخلفية؛ تُستعاد المحاولات عندما يفتح المستخدم التطبيق وتبدأ خدمات النقل، أو عند عودة اتصال أثناء عمل التطبيق.
- طابور النصوص الفردية يعيد إرسال ciphertext كما حُفظ. ملفات المرفقات تعتمد على سجل الملف المحلي وطلبات الأجزاء الناقصة، ولا يعيد runtime بث كل الملف عشوائياً.
- رسائل المجتمعات تبقى على بروتوكول مفاتيح المجموعات والـ Mesh الحالي؛ أعيد إرسال حزم المجتمع المشفرة نفسها من الصندوق، وتُعالج إيصالات المجتمع داخل Group E2E envelope.
- لم يتم بناء APK أو تشغيل `flutter analyze`/اختبارات Dart أو اختبار هاتفين فعليين لعدم توفر أدوات Flutter/Dart/Gradle في بيئة التنفيذ.
